Autoware 1.7.1 as a local APT repository, patch release `-2`.

## What's new in `-2`

- **ML models are downloaded per user.** `autoware-full-1-7-1` depends on
  `autoware-model-downloader-1-7-1` instead of `autoware-data-1-7-1`. Run
  `autoware-download-models-1-7-1` as your own user to fetch the models into
  `~/autoware_data`, where TensorRT can cache its engines. The 2 GB data deb
  is now needed only offline.
- **arm64 servers:** new `ubuntu2204sbsa` build for Grace and Ampere Altra
  machines.
- **GPU coverage:** code for Turing (sm_75; universe 0.50.0 had dropped it,
  which left the occupancy grid map without any kernel for an RTX 20 or T4),
  A100 (sm_80), H100 (sm_90) and B200 (sm_100), and compute_75 PTX for the
  rest. The Jetson build no longer compiles for GPUs L4T's CUDA cannot target.
- **Coexists with other versions:** the theme script is now
  `/usr/bin/apply-autoware-theme-1-7-1`. Update any script that calls
  `apply-autoware-theme`.
- **Complete uninstall:** `uninstall-autoware.sh` gains `--purge` and `-y`,
  as in 1.5.0-3. It removes 1.7.1 only and leaves other installed versions
  alone.

## Download

Pick the localrepo package for your machine. Every package is suffixed `-1-7-1`.

| File | Platform |
|------|----------|
| `autoware-localrepo-1-7-1_1.7.1-2ubuntu2204_all.deb` | Ubuntu 22.04, x86_64 |
| `autoware-localrepo-1-7-1_1.7.1-2ubuntu2204sbsa_all.deb` | Ubuntu 22.04, arm64 server (SBSA: Grace, Ampere Altra) |
| `autoware-localrepo-1-7-1_1.7.1-2jetpack62_all.deb` | JetPack 6.2, Jetson Orin |
| `SHA256SUMS.txt` | checksums |

The ML models are not part of this release: `autoware-download-models-1-7-1`
fetches them (see "Install the ML models"). For machines that cannot reach the
model servers, they are packaged separately in
[Autoware 1.7.1 ML models 1.7.1-1 (offline)](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-1.7.1-1).

Source: [`NEWSLabNTU/autoware` @ `1.7.1-2`](https://github.com/NEWSLabNTU/autoware/tree/1.7.1-2), upstream Autoware 1.7.1 (universe 0.50.0) plus NEWSLab build patches. The
JetPack 6.2 build uses [`1.7.1-1`](https://github.com/NEWSLabNTU/autoware/tree/1.7.1-1)
(`a2dda03`), one commit later, which also drops the GPU targets L4T's CUDA
cannot build.

## Install Autoware

```bash
# (Optional) verify the download
sha256sum --ignore-missing -c SHA256SUMS.txt

# 1. Install the localrepo package (use ubuntu2204sbsa or jetpack62 to match your machine)
sudo dpkg -i autoware-localrepo-1-7-1_1.7.1-2ubuntu2204_all.deb

# 2. Install prerequisites (ROS 2 Humble, optionally CUDA, TensorRT, SpConv)
sudo /usr/share/autoware/1.7.1/setup-prerequisites.sh

# 3. Install Autoware from the localrepo
sudo apt update
sudo apt install autoware-full-1-7-1

# 4. Apply the DDS network settings (sysctl and loopback multicast)
sudo /usr/share/autoware/1.7.1/activate-dds-config.sh

# 5. Source the environment
source /opt/autoware/1.7.1/setup.bash          # workspace (ament, ROS)
source /opt/autoware/1.7.1/autoware-env.bash   # DDS, CycloneDDS, Qt
```

Autoware is installed now, but the perception and planning nodes still need
their ML models; see the next section.

## Install the ML models

The models go into `~/autoware_data`, Autoware's default `data_path`, owned
by the user who launches Autoware. That user must be able to write there: on
first launch TensorRT compiles each model into an `.engine` file next to it
and reuses it afterwards. So set the models up as that user, **not with sudo**.
The tool refuses to run as root unless you give `--dir`.

### Download (recommended)

```bash
autoware-download-models-1-7-1
```

It fetches every model from its upstream URL and checks each file's sha256.
Re-running resumes partial downloads and skips files that already verify.
`--list` shows the models; `--only lidar_centerpoint,tensorrt_yolox` or
`--group perception3d|planning|vision` fetches a subset, so a lidar-only
vehicle needs tens of MB rather than the full set.

### Offline, from the autoware-data debs

For a machine that cannot reach the model servers (`awf.ml.dev.web.auto`,
Hugging Face, S3). Download the `autoware-data-1-7-1` debs from
[Autoware 1.7.1 ML models 1.7.1-1 (offline)](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-1.7.1-1), copy them over, install
them, and link the files into `~/autoware_data`:

```bash
# Install the models under /opt/autoware/1.7.1/data
sudo dpkg -i autoware-data-1-7-1_1.7.1-1_all.deb

# Link them into ~/autoware_data, then check them
autoware-download-models-1-7-1 --link-from /opt/autoware/1.7.1/data
autoware-download-models-1-7-1 --verify
```

The files stay in the root-owned `/opt/autoware/1.7.1/data`, and
`~/autoware_data` gets your own directories with symlinks to them, so TensorRT
can still write its engines there. `--only` and `--group` work here too.

Run the planning simulator with the bundled sample map:

```bash
ros2 launch autoware_launch planning_simulator.launch.xml \
```

## Upgrading from 1.7.1-1

The rebuilt packages keep their version numbers, so `apt upgrade` would leave
the old builds installed. Remove them and install again:

```bash
# 1. Replace the localrepo package. This brings the new uninstall script.
sudo dpkg -i autoware-localrepo-1-7-1_1.7.1-2ubuntu2204_all.deb   # or ubuntu2204sbsa, jetpack62

# 2. Remove the 1.7.1-1 packages, keeping the localrepo.
#    Answer "n" when it offers apt autoremove: step 3 needs those dependencies again.
sudo /usr/share/autoware/1.7.1/uninstall-autoware.sh

# 3. Install 1.7.1-2
sudo apt update
sudo apt install autoware-full-1-7-1

# 4. Install the models as your own user, not sudo (or offline, see "Install the ML models")
autoware-download-models-1-7-1
```

Step 2 also removes the `autoware-data-1-7-1` deb that 1.7.1-1 required, and
the models it installed under `/opt/autoware/1.7.1/data`; step 4 replaces them
in `~/autoware_data`.

- **`data_path`:** if your launch passed `data_path:=/opt/autoware/1.7.1/data`,
  drop it. The default, `$HOME/autoware_data`, is where the models are now.
- **Existing `~/autoware_data`:** the downloader keeps files whose checksum
  matches, replaces those that differ, and deletes the engine built from any
  model it replaces, because TensorRT would otherwise load the old engine.
- **Theme:** `apply-autoware-theme` is now `apply-autoware-theme-1-7-1`.

## Supported NVIDIA GPUs

Turing or newer. TensorRT 10 does not support Volta or Pascal (V100, GTX 10xx).

| GPU | x86_64 | arm64 server | Jetson |
|---|---|---|---|
| Turing: RTX 20, T4, T4G | yes | yes |  |
| Ampere: A100, A30, RTX 30, A10, A40 | yes | yes |  |
| Ada: RTX 40, L4, L40 | yes | yes |  |
| Hopper: H100, H200, GH200 | yes | yes |  |
| Blackwell: B200, GB200 | yes | no |  |
| Blackwell: RTX 50, RTX PRO 6000 | yes |  |  |
| Orin |  |  | yes |

- **arm64 servers:** these use TensorRT 10.3, the newest NVIDIA publishes for
  Ubuntu 22.04 arm64 servers, and it cannot build engines for Blackwell.
- **Drivers:** one that supports CUDA 12.8 (R570 or newer) on x86_64, CUDA
  12.5 on arm64 servers. Jetson uses the JetPack 6.2 stack.

## Several Autoware versions on one machine

1.7.1 installs beside other versions. Package names carry the version and each
version lives in `/opt/autoware/<version>`. Keep each version's models in their
own directory:

```bash
autoware-download-models-1-7-1 --dir ~/autoware_data-1.7.1
ros2 launch autoware_launch ... data_path:=$HOME/autoware_data-1.7.1
```

The downloader stamps the directory with its version and refuses to mix two
versions' models without `--force`.

Releases before 1.5.0-3 and 1.7.1-2 (1.5.0-1, 1.5.0-2, 1.7.1-1) all install
`/usr/bin/apply-autoware-theme` and cannot sit beside another version. Upgrade
them to 1.5.0-3 or 1.7.1-2 first; each of those releases describes how.

## Removal

```bash
# Remove Autoware 1.7.1, keeping its localrepo for a quick reinstall
sudo /usr/share/autoware/1.7.1/uninstall-autoware.sh

# Remove 1.7.1 completely: packages, config files, the localrepo and /opt/autoware/1.7.1
sudo /usr/share/autoware/1.7.1/uninstall-autoware.sh --purge
```

The script removes Autoware 1.7.1 only. Other installed versions keep their
packages; remove each with its own script, e.g.
`/usr/share/autoware/1.9.0/uninstall-autoware.sh`.

The script lists what it will remove and asks first; `-y` skips the
questions. It then lists the dependencies Autoware pulled in that nothing else
needs any more, and asks separately before running `apt autoremove`. Other
Autoware versions and packages you installed yourself keep what they depend on.

It does not touch:

- the prerequisites (ROS 2, CUDA, TensorRT);
- the models in each user's `~/autoware_data`. The script lists those
  directories; delete them yourself with `rm -rf ~/autoware_data`.
