Autoware 1.9.0 as a local APT repository: one Debian package that carries
494 ROS 2 Humble packages and installs them offline through apt. This is the
first 1.9.0 release.

## Highlights

- **Three platforms:** Ubuntu 22.04 x86_64, Ubuntu 22.04 arm64 servers (new,
  `ubuntu2204sbsa`) and Jetson Orin on JetPack 6.2.
- **ML models are downloaded per user,** not shipped in the localrepo, which
  keeps it near 210 MB. `autoware-download-models-1-9-0` fetches them into
  `~/autoware_data` and checks every file. The `autoware-data-1-9-0` debs
  remain for offline installs.
- **Wide GPU coverage:** Turing to Blackwell on x86_64, including RTX 50 and
  B200. See below.
- **Installs beside other Autoware versions,** and uninstalls completely
  with `uninstall-autoware.sh --purge`.

## Install Autoware

```bash
# (Optional) verify the download
sha256sum --ignore-missing -c SHA256SUMS.txt

# 1. Install the localrepo package (use ubuntu2204sbsa or jetpack62 to match your machine)
sudo dpkg -i autoware-localrepo-1-9-0_1.9.0-1ubuntu2204_all.deb

# 2. Install prerequisites (ROS 2 Humble, optionally CUDA, TensorRT, SpConv)
sudo /usr/share/autoware/1.9.0/setup-prerequisites.sh

# 3. Install Autoware from the localrepo
sudo apt update
sudo apt install autoware-full-1-9-0

# 4. Apply the DDS network settings (sysctl and loopback multicast)
sudo /usr/share/autoware/1.9.0/activate-dds-config.sh

# 5. Source the environment
source /opt/autoware/1.9.0/setup.bash          # workspace (ament, ROS)
source /opt/autoware/1.9.0/autoware-env.bash   # DDS, CycloneDDS, Qt
```

Autoware is installed now, but the perception and planning nodes still need
their ML models; see the next section.

## Install the ML models

The models go into `~/autoware_data`, Autoware's default `data_path`, owned
by the user who launches Autoware. That user must be able to write there: on
first launch TensorRT compiles each model into an `.engine` file next to it
and reuses it afterwards. So set the models up as that user, **not with sudo**.
The tool refuses to run as root unless you give `--dir`.

### Download (recommended)

```bash
autoware-download-models-1-9-0
```

It fetches every model from its upstream URL and checks each file's sha256.
Re-running resumes partial downloads and skips files that already verify.
`--list` shows the models; `--only lidar_centerpoint,tensorrt_yolox` or
`--group perception3d|planning|vision` fetches a subset, so a lidar-only
vehicle needs tens of MB rather than the full set.

### Offline, from the autoware-data debs

For a machine that cannot reach the model servers (`awf.ml.dev.web.auto`,
Hugging Face, S3). Copy the `autoware-data-1-9-0*` debs from this release
over, install them, and link the files into `~/autoware_data`:

```bash
# Install the models under /opt/autoware/1.9.0/data
sudo dpkg -i autoware-data-*1-9-0_1.9.0-1_all.deb

# Link them into ~/autoware_data, then check them
autoware-download-models-1-9-0 --link-from /opt/autoware/1.9.0/data
autoware-download-models-1-9-0 --verify
```

The files stay in the root-owned `/opt/autoware/1.9.0/data`, and
`~/autoware_data` gets your own directories with symlinks to them, so TensorRT
can still write its engines there. `--only` and `--group` work here too.


## Upgrading

1.9.0-1 is the first 1.9.0 release; there is nothing to upgrade from. It
installs beside 1.5.0 or 1.7.1 rather than replacing them (see below), so a
machine can keep its current version while 1.9.0 is tried.

## Supported NVIDIA GPUs

Turing or newer. TensorRT 10 does not support Volta or Pascal (V100, GTX 10xx).

| GPU | x86_64 | arm64 server | Jetson |
|---|---|---|---|
| Turing: RTX 20, T4, T4G | yes | yes |  |
| Ampere: A100, A30, RTX 30, A10, A40 | yes | yes |  |
| Ada: RTX 40, L4, L40 | yes | yes |  |
| Hopper: H100, H200, GH200 | yes | yes |  |
| Blackwell: B200, GB200 | yes | no |  |
| Blackwell: RTX 50, RTX PRO 6000 | yes |  |  |
| Orin |  |  | yes |

- **arm64 servers:** these use TensorRT 10.3, the newest NVIDIA publishes for
  Ubuntu 22.04 arm64 servers, and it cannot build engines for Blackwell.
- **Drivers:** one that supports CUDA 12.8 (R570 or newer) on x86_64, CUDA
  12.5 on arm64 servers. Jetson uses the JetPack 6.2 stack.

## Several Autoware versions on one machine

1.9.0 installs beside other versions. Package names carry the version and each
version lives in `/opt/autoware/<version>`. Keep each version's models in their
own directory:

```bash
autoware-download-models-1-9-0 --dir ~/autoware_data-1.9.0
ros2 launch autoware_launch ... data_path:=$HOME/autoware_data-1.9.0
```

The downloader stamps the directory with its version and refuses to mix two
versions' models without `--force`.

Releases before 1.5.0-3 and 1.7.1-2 (1.5.0-1, 1.5.0-2, 1.7.1-1) all install
`/usr/bin/apply-autoware-theme` and cannot sit beside another version. Upgrade
them to 1.5.0-3 or 1.7.1-2 first; each of those releases describes how.

## Removal

```bash
# Remove Autoware 1.9.0, keeping its localrepo for a quick reinstall
sudo /usr/share/autoware/1.9.0/uninstall-autoware.sh

# Remove 1.9.0 completely: packages, config files, the localrepo and /opt/autoware/1.9.0
sudo /usr/share/autoware/1.9.0/uninstall-autoware.sh --purge
```

The script removes Autoware 1.9.0 only. Other installed versions keep their
packages; remove each with its own script, e.g.
`/usr/share/autoware/1.5.0/uninstall-autoware.sh`.

The script lists what it will remove and asks first; `-y` skips the
questions. It then lists the dependencies Autoware pulled in that nothing else
needs any more, and asks separately before running `apt autoremove`. Other
Autoware versions and packages you installed yourself keep what they depend on.

It does not touch:

- the prerequisites (ROS 2, CUDA, TensorRT);
- the models in each user's `~/autoware_data`. The script lists those
  directories; delete them yourself with `rm -rf ~/autoware_data`.
