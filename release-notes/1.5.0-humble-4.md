Autoware 1.5.0 as a local APT repository, patch release `-4`. The first 1.5.0
tag to name its ROS distro: `1.5.0-humble-4`.

## What's new in `-4`

- **Perception and the CUDA point cloud preprocessor load again.** 1.5.0-3
  was built against ROS Humble's `diagnostic_updater` 4.0.7, which (unlike
  4.0.6 and earlier) keeps `diagnostic_updater::Updater`'s vtable in
  `libdiagnostic_updater.so` instead of in every user's headers. Six
  libraries used `Updater` without linking that library, so each failed to
  load (`undefined symbol: _ZTVN18diagnostic_updater7UpdaterE`) unless another
  component in the same container had loaded it first. Autoware perception
  could fail to start under plain `ros2 launch`, depending on load order.
  Affected: `autoware_compare_map_segmentation`, `concatenate_data`
  (`autoware_pointcloud_preprocessor`), `autoware_lidar_centerpoint`,
  `autoware_lidar_transfusion`, `autoware_bevfusion` and
  `autoware_cuda_pointcloud_preprocessor` (the GPU-free builds have the first
  two). They now link `diagnostic_updater`
  ([autoware_universe 1.5.0-patches `4df1b60`](https://github.com/NEWSLabNTU/autoware_universe/commit/4df1b60)).
- **The CUDA runtime is installed.** On x86_64 and arm64 servers,
  `setup-prerequisites.sh` installed the CUDA math libraries but not
  `cuda-cudart-12-4`, so the CUDA packages could not find `libcudart.so.12`
  on a host without its own CUDA toolkit. On an existing install, add it with
  `sudo apt install cuda-cudart-12-4`. JetPack ships the runtime.
- Everything else is as in
  [1.5.0-3](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/1.5.0-3);
  its notes describe the per-user ML models, the arm64 server and GPU-free
  builds, and the uninstall script.
- **Not fixed yet:** the CMake export files of six packages
  (`autoware_pointcloud_preprocessor`, `nebula_ros`, `nebula_decoders`,
  `nebula_hw_interfaces`, `llh_converter`, `eagleye_navigation`) still name the
  builder's `/output/workspace/install` path, so a package that
  `find_package`s one of them cannot be built against this release.

## Download

Pick the localrepo package for your machine. Every package is suffixed `-1-5-0`.

| File | Platform |
|------|----------|
| `autoware-localrepo-1-5-0_1.5.0-4ubuntu2204_all.deb` | Ubuntu 22.04, x86_64 |
| `autoware-localrepo-1-5-0_1.5.0-4ubuntu2204sbsa_all.deb` | Ubuntu 22.04, arm64 server (SBSA: Grace, Ampere Altra) |
| `autoware-localrepo-1-5-0_1.5.0-4jetpack62_all.deb` | JetPack 6.2, Jetson Orin |
| `autoware-localrepo-1-5-0_1.5.0-4ubuntu2204cpu_all.deb` | Ubuntu 22.04, x86_64, no NVIDIA GPU |
| `autoware-localrepo-1-5-0_1.5.0-4ubuntu2204arm64cpu_all.deb` | Ubuntu 22.04, any arm64 machine, no NVIDIA GPU |
| `SHA256SUMS.txt` | checksums |

The ML models are not part of this release: `autoware-download-models-1-5-0`
fetches them (see "Install the ML models"). For machines that cannot reach the
model servers, they are packaged separately in
[Autoware 1.5.0 ML models 1.5.0-1 (offline)](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-1.5.0-1).

Source: [`NEWSLabNTU/autoware` @ `1.5.0-humble-4`](https://github.com/NEWSLabNTU/autoware/tree/1.5.0-humble-4), upstream Autoware 1.5.0 (universe 0.48.0) plus NEWSLab build patches.

## Install Autoware

```bash
# (Optional) verify the download
sha256sum --ignore-missing -c SHA256SUMS.txt

# 1. Install the localrepo package (use ubuntu2204sbsa or jetpack62 to match your machine)
sudo dpkg -i autoware-localrepo-1-5-0_1.5.0-4ubuntu2204_all.deb

# 2. Install prerequisites (ROS 2 Humble, optionally CUDA, TensorRT, SpConv)
sudo /usr/share/autoware/1.5.0/setup-prerequisites.sh

# 3. Install Autoware from the localrepo
sudo apt update
sudo apt install autoware-full-1-5-0

# 4. Apply the DDS network settings (sysctl and loopback multicast)
sudo /usr/share/autoware/1.5.0/activate-dds-config.sh

# 5. Source the environment
source /opt/autoware/1.5.0/setup.bash          # workspace (ament, ROS)
source /opt/autoware/1.5.0/autoware-env.bash   # DDS, CycloneDDS, Qt
```

Autoware is installed now, but the perception and planning nodes still need
their ML models; see the next section.

## Install the ML models

The models go into `~/autoware_data`, Autoware's default `data_path`, owned
by the user who launches Autoware. That user must be able to write there: on
first launch TensorRT compiles each model into an `.engine` file next to it
and reuses it afterwards. So set the models up as that user, **not with sudo**.
The tool refuses to run as root unless you give `--dir`.

### Download (recommended)

```bash
autoware-download-models-1-5-0
```

It fetches every model from its upstream URL and checks each file's sha256.
Re-running resumes partial downloads and skips files that already verify.
`--list` shows the models; `--only lidar_centerpoint,tensorrt_yolox` or
`--group perception3d|planning|vision` fetches a subset, so a lidar-only
vehicle needs tens of MB rather than the full set.

### Offline, from the autoware-data debs

For a machine that cannot reach the model servers (`awf.ml.dev.web.auto`,
Hugging Face, S3). Download the `autoware-data-1-5-0` debs from
[Autoware 1.5.0 ML models 1.5.0-1 (offline)](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-1.5.0-1), copy them over, install
them, and link the files into `~/autoware_data`:

```bash
# Install the models under /opt/autoware/1.5.0/data
sudo dpkg -i autoware-data-1-5-0_1.5.0-1_all.deb

# Link them into ~/autoware_data, then check them
autoware-download-models-1-5-0 --link-from /opt/autoware/1.5.0/data
autoware-download-models-1-5-0 --verify
```

The files stay in the root-owned `/opt/autoware/1.5.0/data`, and
`~/autoware_data` gets your own directories with symlinks to them, so TensorRT
can still write its engines there. `--only` and `--group` work here too.

## Try it

Run the planning simulator with the bundled sample map.
The sample maps are their own package in 1.5.0; install it first:
`sudo apt install autoware-maps-1-5-0`.

```bash
ros2 launch autoware_launch planning_simulator.launch.xml \
  map_path:=/opt/autoware/1.5.0/share/autoware_maps/sample-map-planning \
  vehicle_model:=sample_vehicle sensor_model:=sample_sensor_kit
```

## Upgrading from 1.5.0-3 (or earlier)

The rebuilt packages keep their version numbers, so `apt upgrade` leaves the
broken builds installed. Remove them and install again:

```bash
# 1. Replace the localrepo package
sudo dpkg -i autoware-localrepo-1-5-0_1.5.0-4ubuntu2204_all.deb   # or your platform's

# 2. Remove the old packages, keeping the localrepo.
#    Answer "n" when it offers apt autoremove: step 3 needs those dependencies again.
sudo /usr/share/autoware/1.5.0/uninstall-autoware.sh

# 3. Install 1.5.0-4
sudo apt update
sudo apt install autoware-full-1-5-0
```

Your models in `~/autoware_data` and their TensorRT engines are kept. From
1.5.0-1 or 1.5.0-2, also follow the upgrade notes of
[1.5.0-3](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/1.5.0-3)
(the models moved to `~/autoware_data`, the theme script was renamed).

To check an install, this should print nothing:

```bash
for f in /opt/autoware/1.5.0/lib/*.so; do
  readelf --dyn-syms -W "$f" | grep -q ' UND _ZTVN18diagnostic_updater7UpdaterE' &&
    ! readelf -d "$f" | grep -q libdiagnostic_updater && echo "$f"
done
```

## Supported NVIDIA GPUs

Turing or newer. TensorRT 10 does not support Volta or Pascal (V100, GTX 10xx).

| GPU | x86_64 | arm64 server | Jetson |
|---|---|---|---|
| Turing: RTX 20, T4, T4G | yes | yes |  |
| Ampere: A100, A30, RTX 30, A10, A40 | yes | yes |  |
| Ada: RTX 40, L4, L40 | yes | yes |  |
| Hopper: H100, H200, GH200 | yes | yes |  |
| Blackwell: B200, GB200, RTX 50 | no | no |  |
| Orin |  |  | yes |

- **Blackwell:** 1.5.0 is built with CUDA 12.4, which cannot target it. The
  occupancy grid map library carries only code for the GPUs it was built for,
  so it fails on any Blackwell GPU. Use 1.9.0 there.
- **Drivers:** one that supports CUDA 12.8 (R570 or newer) on x86_64, CUDA
  12.5 on arm64 servers. Jetson uses the JetPack 6.2 stack.

## Machines without an NVIDIA GPU

`ubuntu2204cpu` (x86_64) and `ubuntu2204arm64cpu` (any arm64
machine) are the same Autoware 1.5.0 built without CUDA, cuDNN or TensorRT;
nothing in them needs an NVIDIA library. Install them as above, but give the
prerequisites script `--ros` alone, and skip the ML models:

```bash
sudo dpkg -i autoware-localrepo-1-5-0_1.5.0-4ubuntu2204cpu_all.deb   # or ubuntu2204arm64cpu
sudo /usr/share/autoware/1.5.0/setup-prerequisites.sh --non-interactive --ros
sudo apt update && sudo apt install autoware-full-1-5-0
```

- **Works:** planning, control, NDT localization, the planning simulator (tested:
  it drives the sample map to its goal on both architectures), and LiDAR
  detection by Euclidean clustering.
- **Missing:** every neural network (CenterPoint, TransFusion, BEVFusion, YOLOX,
  the traffic light classifiers), the CUDA pointcloud preprocessor and ground
  segmentation, and the pointcloud-based occupancy grid map. Those packages are
  installed empty so the rest still resolves.
- **Perception must be told:** launch with `lidar_detection_model:=clustering`
  and `occupancy_grid_map_method:=laserscan_based`; the defaults name GPU nodes
  that are not there. This perception setup is not yet tested.

A CPU and a CUDA localrepo of 1.5.0 have the same package names, so a machine
runs one of them; to switch, remove the other with `uninstall-autoware.sh --purge` first.

## Several Autoware versions on one machine

1.5.0 installs beside other versions. Package names carry the version and each
version lives in `/opt/autoware/<version>`. Keep each version's models in their
own directory:

```bash
autoware-download-models-1-5-0 --dir ~/autoware_data-1.5.0
ros2 launch autoware_launch ... data_path:=$HOME/autoware_data-1.5.0
```

The downloader stamps the directory with its version and refuses to mix two
versions' models without `--force`.

Releases before 1.5.0-3 and 1.7.1-2 (1.5.0-1, 1.5.0-2, 1.7.1-1) all install
`/usr/bin/apply-autoware-theme` and cannot sit beside another version. Upgrade
them to 1.5.0-4 or 1.7.1-2 first; each of those releases describes how.

## Removal

```bash
# Remove Autoware 1.5.0, keeping its localrepo for a quick reinstall
sudo /usr/share/autoware/1.5.0/uninstall-autoware.sh

# Remove 1.5.0 completely: packages, config files, the localrepo and /opt/autoware/1.5.0
sudo /usr/share/autoware/1.5.0/uninstall-autoware.sh --purge
```

The script removes Autoware 1.5.0 only. Other installed versions keep their
packages; remove each with its own script, e.g.
`/usr/share/autoware/1.9.0/uninstall-autoware.sh`.

The script lists what it will remove and asks first; `-y` skips the
questions. It then lists the dependencies Autoware pulled in that nothing else
needs any more, and asks separately before running `apt autoremove`. Other
Autoware versions and packages you installed yourself keep what they depend on.

It does not touch:

- the prerequisites (ROS 2, CUDA, TensorRT);
- the models in each user's `~/autoware_data`. The script lists those
  directories; delete them yourself with `rm -rf ~/autoware_data`.
