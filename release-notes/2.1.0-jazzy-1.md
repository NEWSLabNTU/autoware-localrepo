Autoware 2.1.0 for ROS 2 Jazzy (Ubuntu 24.04) as a local APT repository: one
Debian package that carries 502 ROS 2 Jazzy packages and installs them
offline through apt. It is the same Autoware 2.1.0 as
[2.1.0-1](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/2.1.0-1),
which is for ROS 2 Humble (Ubuntu 22.04), built for Jazzy instead.

This is the first release whose tag names its ROS distro. Every new release
does from now on (`2.1.0-jazzy-1`, and the next Humble one `2.1.0-humble-2`).
Releases already published keep their tags.

## Highlights

- **Upstream Autoware 2.1.0** (2026-11-10): universe 0.53.2, core 1.10.0 and
  `autoware_cuda`, from the same workspace commit as the Humble release.
- **ROS 2 Jazzy on Ubuntu 24.04,** with upstream's Jazzy stack: CUDA 13.0,
  TensorRT 10.13.3.9, cuDNN 9 for CUDA 13, spconv 2.3.8 for CUDA 13.0.
- **ML models are downloaded per user,** as for Humble 2.1.0. The models are
  the same for both distros, so the offline packages are the existing
  [data-2.1.0-1](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-2.1.0-1)
  release. There is no Jazzy data release.
- **A GPU-free build** for x86_64 machines without an NVIDIA GPU.

## Download

Pick the localrepo package for your machine. Every package is suffixed `-2-1-0`.

| File | Platform |
|------|----------|
| `autoware-localrepo-2-1-0_2.1.0-1ubuntu2404_all.deb` | Ubuntu 24.04, x86_64 |
| `autoware-localrepo-2-1-0_2.1.0-1ubuntu2404cpu_all.deb` | Ubuntu 24.04, x86_64, no NVIDIA GPU |
| `autoware-localrepo-2-1-0_2.1.0-1jetpack72_all.deb` | JetPack 7.2 (Ubuntu 24.04), Jetson. **Pending:** built separately and added to this release when it has been tested |
| `SHA256SUMS.txt` | checksums |

An arm64 server package for Jazzy is not listed yet.

The ML models are not part of this release: `autoware-download-models-2-1-0`
fetches them (see "Install the ML models"). For machines that cannot reach
the model servers, they are packaged in
[Autoware 2.1.0 ML models 2.1.0-1 (offline)](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-2.1.0-1),
the same packages Humble 2.1.0 uses.

Source: [`NEWSLabNTU/autoware` @ `2.1.0-1`](https://github.com/NEWSLabNTU/autoware/tree/2.1.0-1),
the same as Humble 2.1.0-1, with its NEWSLab build patches (see the
[2.1.0-1 notes](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/2.1.0-1)).
Two build fixes are Jazzy-only:

- colcon2deb wrote `/opt/ros/humble` into every package's `debian/rules`, so
  under Jazzy the packaging step found no ROS packages
  (colcon2deb [`0b1f427`](https://github.com/NEWSLabNTU/colcon2deb/commit/0b1f427)).
- `autoware_path_optimizer` builds with `-Werror`. On Ubuntu 24.04, GCC 13
  warns falsely that a variable may be used uninitialized, inside boost 1.83's
  `boost::geometry`. That warning is kept non-fatal for this one package.
- Jazzy's `rmw_cyclonedds_cpp` gives each process an automatic DDS participant
  index, at most 32 by default. Autoware runs more processes than that, and the
  ones past 32 aborted at start ("Failed to find a free participant index").
  The CycloneDDS profile that `autoware-env.bash` selects now allows 120.
  **Source `/opt/autoware/2.1.0/autoware-env.bash`** (step 5) before launching:
  without it the planning simulator loses about 20 of its processes.
- `setup-prerequisites.sh` removes a CUDA apt source that has no `signed-by`,
  as the `nvidia/cuda` Ubuntu 24.04 images ship. Otherwise `cuda-keyring` adds
  the same repository again with `signed-by`, and apt refuses to update.

## Install Autoware

```bash
# (Optional) verify the download
sha256sum --ignore-missing -c SHA256SUMS.txt

# 1. Install the localrepo package
sudo dpkg -i autoware-localrepo-2-1-0_2.1.0-1ubuntu2404_all.deb

# 2. Install prerequisites (ROS 2 Jazzy, optionally CUDA 13.0, TensorRT, SpConv)
sudo /usr/share/autoware/2.1.0/setup-prerequisites.sh

# 3. Install Autoware from the localrepo
sudo apt update
sudo apt install autoware-full-2-1-0

# 4. Apply the DDS network settings (sysctl and loopback multicast)
sudo /usr/share/autoware/2.1.0/activate-dds-config.sh

# 5. Source the environment
source /opt/autoware/2.1.0/setup.bash          # workspace (ament, ROS)
source /opt/autoware/2.1.0/autoware-env.bash   # DDS, CycloneDDS, Qt
```

`setup-prerequisites.sh` stops on anything but Ubuntu 24.04, so the Jazzy
package cannot be set up on a Humble machine by mistake.

Autoware is installed now, but the perception and planning nodes still need
their ML models; see the next section.

## Install the ML models

As for Humble 2.1.0. The models go into `~/autoware_data`, Autoware's default
`data_path`, owned by the user who launches Autoware. Set them up as that
user, **not with sudo**:

```bash
autoware-download-models-2-1-0
```

`--list`, `--only` and `--group` work as for Humble. Offline, install the
`autoware-data-*2-1-0` debs from
[data-2.1.0-1](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-2.1.0-1)
and link them in:

```bash
sudo dpkg -i autoware-data-*2-1-0_2.1.0-1_all.deb
autoware-download-models-2-1-0 --link-from /opt/autoware/2.1.0/data
autoware-download-models-2-1-0 --verify
```

## Try it

```bash
ros2 launch autoware_launch planning_simulator.launch.xml \
  map_path:=/opt/autoware/2.1.0/share/autoware_maps/sample-map-planning \
  vehicle_model:=sample_vehicle sensor_model:=sample_sensor_kit
```

## Testing

Both x86_64 packages were installed in clean Ubuntu 24.04 containers from the
localrepo alone, and every ELF file under `/opt/autoware/2.1.0` was run
through `ldd`. None had an unresolved library: 1508 files for `ubuntu2404`
(with the CUDA 13.0, cuDNN and TensorRT runtime from `setup-prerequisites.sh`)
and 1423 for `ubuntu2404cpu` (ROS only). The GPU-free package was also driven
headless in the planning simulator, which engaged and drove the sample map to
its goal (81.6 m). The CUDA package was tested by installation only; its
CUDA and TensorRT code has not yet run on a GPU.

## Upgrading

2.1.0-jazzy-1 is the first Jazzy release, so there is nothing to upgrade from.
An Ubuntu 22.04 machine on Humble 2.1.0-1 does not move to it in place: Jazzy
needs Ubuntu 24.04. After upgrading the OS, install this release fresh.

## Supported NVIDIA GPUs

Turing or newer, with a driver that supports CUDA 13.0 (R580 or newer).

| GPU | x86_64 |
|---|---|
| Turing: RTX 20, T4 | yes |
| Ampere: A100, A30, RTX 30, A10, A40 | yes |
| Ada: RTX 40, L4, L40 | yes |
| Hopper: H100, H200 | yes |
| Blackwell: B200, GB200 | yes |
| Blackwell: RTX 50, RTX PRO 6000 | yes |

## Machines without an NVIDIA GPU

`ubuntu2404cpu` is the same Autoware 2.1.0 for Jazzy built without CUDA,
cuDNN or TensorRT. Install it as above, but give the prerequisites script
`--ros` alone, and skip the ML models:

```bash
sudo dpkg -i autoware-localrepo-2-1-0_2.1.0-1ubuntu2404cpu_all.deb
sudo /usr/share/autoware/2.1.0/setup-prerequisites.sh --non-interactive --ros
sudo apt update && sudo apt install autoware-full-2-1-0
```

What works and what is missing is as for Humble's `ubuntu2204cpu`. Planning,
control, NDT localization, the planning simulator and Euclidean-clustering
detection work. Every neural network and the CUDA point cloud stages are
missing. Launch with `lidar_detection_model:=clustering` and
`occupancy_grid_map_method:=laserscan_based`.

## Several Autoware versions on one machine

As for Humble: each version lives in `/opt/autoware/<version>`. There is only
one Jazzy version so far.

## Removal

```bash
sudo /usr/share/autoware/2.1.0/uninstall-autoware.sh           # keep the localrepo
sudo /usr/share/autoware/2.1.0/uninstall-autoware.sh --purge   # remove everything of 2.1.0
```

It leaves ROS 2, CUDA and TensorRT, and the models in each user's
`~/autoware_data`, in place.
