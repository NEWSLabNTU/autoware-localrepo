Autoware 2.1.0 as a local APT repository: one Debian package that carries
502 ROS 2 Humble packages and installs them offline through apt. This is the
first 2.1.0 release, and it is for ROS 2 Humble (Ubuntu 22.04) only.

## Highlights

- **Upstream Autoware 2.1.0** (2026-11-10): universe 0.53.2, core 1.10.0 and
  the new `autoware_cuda` repository.
- **Five platforms from the start:** Ubuntu 22.04 x86_64, Ubuntu 22.04 arm64
  servers, Jetson Orin on JetPack 6.2, and GPU-free builds for x86_64 and
  arm64.
- **ML models are downloaded per user,** not shipped in the localrepo.
  `autoware-download-models-2-1-0` fetches them from Hugging Face into
  `~/autoware_data` and checks every file. The `autoware-data-2-1-0` debs
  remain for offline installs.
- **Installs beside Autoware 1.5.0, 1.7.1 and 1.9.0,** and uninstalls
  completely with `uninstall-autoware.sh --purge`.

## Download

Pick the localrepo package for your machine. Every package is suffixed `-2-1-0`.

| File | Platform |
|------|----------|
| `autoware-localrepo-2-1-0_2.1.0-1ubuntu2204_all.deb` | Ubuntu 22.04, x86_64 |
| `autoware-localrepo-2-1-0_2.1.0-1ubuntu2204sbsa_all.deb` | Ubuntu 22.04, arm64 server (SBSA: Grace, Ampere Altra) |
| `autoware-localrepo-2-1-0_2.1.0-1jetpack62_all.deb` | JetPack 6.2, Jetson Orin |
| `autoware-localrepo-2-1-0_2.1.0-1ubuntu2204cpu_all.deb` | Ubuntu 22.04, x86_64, no NVIDIA GPU |
| `autoware-localrepo-2-1-0_2.1.0-1ubuntu2204arm64cpu_all.deb` | Ubuntu 22.04, any arm64 machine, no NVIDIA GPU |
| `SHA256SUMS.txt` | checksums |

The ML models are not part of this release: `autoware-download-models-2-1-0`
fetches them (see "Install the ML models"). For machines that cannot reach
Hugging Face, they are packaged separately in
[Autoware 2.1.0 ML models 2.1.0-1 (offline)](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-2.1.0-1).

Source: [`NEWSLabNTU/autoware` @ `2.1.0-1`](https://github.com/NEWSLabNTU/autoware/tree/2.1.0-1), upstream Autoware 2.1.0 plus NEWSLab build patches:

- `autoware_universe` 0.53.2 with the acados code generator serialized, so a
  parallel build no longer runs it twice at once
  ([`2.1.0-patches`](https://github.com/NEWSLabNTU/autoware_universe/tree/2.1.0-patches)).
- `autoware_launch` humble 0.53.0 with upstream's perception parameter sync
  (#2002) from its main branch. Without it `map_based_prediction` stops at
  startup on the parameters universe 0.53.2 added, and the vehicle cannot
  be engaged
  ([`2.1.0-patches`](https://github.com/NEWSLabNTU/autoware_launch/tree/2.1.0-patches)).
- On JetPack 6.2 only, `cuda_blackboard` falls back from
  `cudaStreamGetDevice()`, which CUDA 12.6 does not have.

## Install Autoware

```bash
# (Optional) verify the download
sha256sum --ignore-missing -c SHA256SUMS.txt

# 1. Install the localrepo package (use ubuntu2204sbsa or jetpack62 to match your machine)
sudo dpkg -i autoware-localrepo-2-1-0_2.1.0-1ubuntu2204_all.deb

# 2. Install prerequisites (ROS 2 Humble, optionally CUDA, TensorRT, SpConv)
sudo /usr/share/autoware/2.1.0/setup-prerequisites.sh

# 3. Install Autoware from the localrepo
sudo apt update
sudo apt install autoware-full-2-1-0

# 4. Apply the DDS network settings (sysctl and loopback multicast)
sudo /usr/share/autoware/2.1.0/activate-dds-config.sh

# 5. Source the environment
source /opt/autoware/2.1.0/setup.bash          # workspace (ament, ROS)
source /opt/autoware/2.1.0/autoware-env.bash   # DDS, CycloneDDS, Qt
```

Autoware is installed now, but the perception and planning nodes still need
their ML models; see the next section.

## Install the ML models

The models go into `~/autoware_data`, Autoware's default `data_path`, owned
by the user who launches Autoware. That user must be able to write there: on
first launch TensorRT compiles each model into an `.engine` file next to it
and reuses it afterwards. So set the models up as that user, **not with sudo**.
The tool refuses to run as root unless you give `--dir`.

### Download (recommended)

```bash
autoware-download-models-2-1-0
```

It fetches every model from Hugging Face and checks each file's sha256.
Re-running resumes partial downloads and skips files that already verify.
`--list` shows the models; `--only lidar_centerpoint,tensorrt_yolox` or
`--group perception3d|planning|vision` fetches a subset, so a lidar-only
vehicle needs tens of MB rather than the full 2 GB.

### Offline, from the autoware-data debs

For a machine that cannot reach Hugging Face. Download the `autoware-data-2-1-0`
debs from
[Autoware 2.1.0 ML models 2.1.0-1 (offline)](https://github.com/NEWSLabNTU/autoware-localrepo/releases/tag/data-2.1.0-1), copy them over, install
them, and link the files into `~/autoware_data`:

```bash
# Install the models under /opt/autoware/2.1.0/data
sudo dpkg -i autoware-data-*2-1-0_2.1.0-1_all.deb

# Link them into ~/autoware_data, then check them
autoware-download-models-2-1-0 --link-from /opt/autoware/2.1.0/data
autoware-download-models-2-1-0 --verify
```

The files stay in the root-owned `/opt/autoware/2.1.0/data`, and
`~/autoware_data` gets your own directories with symlinks to them, so TensorRT
can still write its engines there. `--only` and `--group` work here too.

## Try it

Run the planning simulator with the bundled sample map:

```bash
ros2 launch autoware_launch planning_simulator.launch.xml \
  map_path:=/opt/autoware/2.1.0/share/autoware_maps/sample-map-planning \
  vehicle_model:=sample_vehicle sensor_model:=sample_sensor_kit
```

## Testing

Every package was installed in a clean container. The arm64 server, JetPack 6.2
and both GPU-free packages were also driven headless in the planning simulator,
which engaged and drove the sample map (about 81.6 m). The x86_64 CUDA package
was tested by installation only. The JetPack 6.2 package was tested in its
L4T container on an arm64 server, not on a Jetson, so its CUDA and TensorRT
code has not yet run on Orin hardware.

## Upgrading

2.1.0-1 is the first 2.1.0 release; there is nothing to upgrade from. It
installs beside 1.5.0, 1.7.1 or 1.9.0 rather than replacing them (see below),
so a machine can keep its current version while 2.1.0 is tried.

## Supported NVIDIA GPUs

Turing or newer. TensorRT 10 does not support Volta or Pascal (V100, GTX 10xx).

| GPU | x86_64 | arm64 server | Jetson |
|---|---|---|---|
| Turing: RTX 20, T4, T4G | yes | yes |  |
| Ampere: A100, A30, RTX 30, A10, A40 | yes | yes |  |
| Ada: RTX 40, L4, L40 | yes | yes |  |
| Hopper: H100, H200, GH200 | yes | yes |  |
| Blackwell: B200, GB200 | yes | no |  |
| Blackwell: RTX 50, RTX PRO 6000 | yes |  |  |
| Orin |  |  | yes |

- **arm64 servers:** these use TensorRT 10.3, the newest NVIDIA publishes for
  Ubuntu 22.04 arm64 servers, and it cannot build engines for Blackwell.
- **Drivers:** one that supports CUDA 12.8 (R570 or newer) on x86_64, CUDA
  12.5 on arm64 servers. Jetson uses the JetPack 6.2 stack (CUDA 12.6,
  TensorRT 10.3).
- **Jetson Thor** needs JetPack 7 and Ubuntu 24.04, so it is not covered by this
  Humble release.

## Machines without an NVIDIA GPU

`ubuntu2204cpu` (x86_64) and `ubuntu2204arm64cpu` (any arm64 machine) are the
same Autoware 2.1.0 built without CUDA, cuDNN or TensorRT; nothing in them
needs an NVIDIA library. Install them as above, but give the prerequisites
script `--ros` alone, and skip the ML models:

```bash
sudo dpkg -i autoware-localrepo-2-1-0_2.1.0-1ubuntu2204cpu_all.deb   # or ubuntu2204arm64cpu
sudo /usr/share/autoware/2.1.0/setup-prerequisites.sh --non-interactive --ros
sudo apt update && sudo apt install autoware-full-2-1-0
```

- **Works:** planning, control, NDT localization, the planning simulator (tested:
  it drives the sample map to its goal on both architectures), and LiDAR
  detection by Euclidean clustering.
- **Missing:** every neural network (CenterPoint, TransFusion, BEVFusion, YOLOX,
  the traffic light classifiers), the CUDA pointcloud preprocessor and ground
  segmentation, and the pointcloud-based occupancy grid map. Those packages are
  installed empty so the rest still resolves.
- **Perception must be told:** launch with `lidar_detection_model:=clustering`
  and `occupancy_grid_map_method:=laserscan_based`; the defaults name GPU nodes
  that are not there. This perception setup is not yet tested.

A CPU and a CUDA localrepo of 2.1.0 have the same package names, so a machine
runs one of them; to switch, remove the other with `uninstall-autoware.sh --purge` first.

## Several Autoware versions on one machine

2.1.0 installs beside other versions. Package names carry the version and each
version lives in `/opt/autoware/<version>`. Keep each version's models in their
own directory:

```bash
autoware-download-models-2-1-0 --dir ~/autoware_data-2.1.0
ros2 launch autoware_launch ... data_path:=$HOME/autoware_data-2.1.0
```

The downloader stamps the directory with its version and refuses to mix two
versions' models without `--force`.

Releases before 1.5.0-3 and 1.7.1-2 (1.5.0-1, 1.5.0-2, 1.7.1-1) all install
`/usr/bin/apply-autoware-theme` and cannot sit beside another version. Upgrade
them to 1.5.0-3 or 1.7.1-2 first; each of those releases describes how.

## Removal

```bash
# Remove Autoware 2.1.0, keeping its localrepo for a quick reinstall
sudo /usr/share/autoware/2.1.0/uninstall-autoware.sh

# Remove 2.1.0 completely: packages, config files, the localrepo and /opt/autoware/2.1.0
sudo /usr/share/autoware/2.1.0/uninstall-autoware.sh --purge
```

The script removes Autoware 2.1.0 only. Other installed versions keep their
packages; remove each with its own script, e.g.
`/usr/share/autoware/1.9.0/uninstall-autoware.sh`.

The script lists what it will remove and asks first; `-y` skips the
questions. It then lists the dependencies Autoware pulled in that nothing else
needs any more, and asks separately before running `apt autoremove`. Other
Autoware versions and packages you installed yourself keep what they depend on.

It does not touch:

- the prerequisites (ROS 2, CUDA, TensorRT);
- the models in each user's `~/autoware_data`. The script lists those
  directories; delete them yourself with `rm -rf ~/autoware_data`.
